# FME用 DEMマージ → CS方式立体図 → 国土基本図図郭分割

バージョン0.8.1（試作）／2026-10-03

Copyright (C) 2026 Yoichi Wada. GNU GPL v3.0 only.

v0.7.1では、FME版マニュアルとForestgeo.infoの公開チューニングを参考に、曲率の青―黄―赤3点補間、5レイヤー加重和、RGB別ストレッチを追加しました。

**v0.7.2の重要な変更**：`color_model: "fme"`の標準曲率範囲は、FMEマニュアル別紙3の明記値である**±0.1（確認済み。FMEワークスペースのRasterConvolverカーネル除数から導出）**です。暫定値**±0.03**は、FME標準値とは別プロファイル `config.forestry_tuned.json` として提供しています。過去バージョン（〜v0.7.1）では両者が標準設定内で混在していたため、v0.7.2で分離しました。詳細は VALIDATION.txt の「v0.7.2 指示書違反の修正」を参照してください。

RGBストレッチは `stretch_mode` （`none` / `nagano_reference` / `custom`）から選択できます。`nagano_reference`（長野県LEMデータによる実績値。全国一律の固定仕様ではありません）が既定です。

森林航空レーザ成果入力として、LEM＋同名CSVヘッダー、XYZ/CSV格子、TIFF＋TFW、GeoTIFFおよびこれらを格納したZIPの自動判別を追加しました。

## 変更した仕様

複数DEMをマージし、地域に適した平面直角座標系でCS方式の画像を作成した後、国土基本図の図郭で分割します。解析後も同じ座標系・セルサイズ・画素値を保持します。

図郭割りと番号は、国土地理院「作業規程の準則 付録7 公共測量標準図式」の数値地形図データファイル仕様・第84～85条に基づきます。PDFの26～30ページ（先頭を1ページとした番号）を参照してください。

[一次資料：付録7（PDF）](https://www.gsi.go.jp/common/000258741.pdf)

図郭GeoTIFF出力に加え、XYZ PNG配信タイルを生成します。詳細は末尾のXYZ一括生成を参照してください。

標準設定の配色・合成はFME参考方式です。ただし、曲率等の地形量算出を含む画素単位の完全一致は、FME実機の同一DEM出力との比較で確認する必要があります。旧版の独自合成は `color_model: "legacy"` で保持します。

FMEマニュアルの曲率範囲（通常±10、10m DEMは±5）はFME内部の曲率値です。本実装の曲率指標（負のラプラシアン近似、1/m）とは数値体系が異なるため、値だけを直接転用していません。

## 対応する図郭

|sheet_level|東西（測量Y方向）|南北（測量X方向）|セル1mの画像寸法（幅×高さ）|番号の例|
|---|---:|---:|---:|---|
|5000|4,000m|3,000m|4,000×3,000px|09LD00|
|2500|2,000m|1,500m|2,000×1,500px|09LD001|
|1000|800m|600m|800×600px|09LD000A|
|500|400m|300m|400×300px|09LD0000|

地図情報レベルの値は、ここでは**図郭の大きさと番号方式を選ぶ設定**です。1m DEMやレベル500の図郭であることだけで、地図情報レベル500の位置精度を満たすとは判断できません。

設定例は5000図郭です。必要に応じて2500・1000・500へ変更します。250図郭、任意の変形図郭、旧日本測地系で作成された図郭を世界測地系へ変換して引き継ぐ特殊ケースには対応していません。

## 実行手順

1. このフォルダーを、例として `D:/CSMap/fme_csmap_pipeline` に展開します。
2. `config.example.json` を `config.json` にコピーして入力先・出力先・座標系・系番号・図郭レベル・セルサイズを設定します。
3. `run_csmap.cmd` のCondaのパスを自分の環境に変更します。
4. 下記で実行環境を作成し、テストします。
5. FMEのSystemCallerから `run_csmap.cmd` を一度だけ起動します。

```bat
conda env create -f environment.yml
conda run -n csmap python -m unittest test_pipeline test_map_sheets test_color -v
```

Conda環境にはPython 3.11、GDAL 3.10以降、NumPy、SciPy、PDAL 2.9以降を指定しています。FME内蔵Pythonへの追加インストールは必要ありません。コードのGDAL API下限は3.6ですが、すべての新しいGDALバージョンでの動作を確認したものではありません。

FMEを介さない実行確認：

```bat
conda run --no-capture-output -n csmap python csmap_pipeline.py --config config.json
```

## FME Workbenchの接続

Creator（生成数1）→ SystemCaller → Tester（終了コードが0）

- SystemCallerのCommand Line：`cmd.exe /d /c D:\CSMap\fme_csmap_pipeline\run_csmap.cmd`
- Exit Code属性名：`cs_exit_code`
- Tester：`cs_exit_code = 0`
- TesterのFailed側：Terminatorへ接続。

上記は呼出し先パスに空白を含めない例です。空白がある場合の引用符は[SystemCaller公式説明](https://docs.safe.com/fme/html/FME-Form-Documentation/FME-Transformers/Transformers/systemcaller.htm)に従ってください。

**DEMごとにSystemCallerを実行しないでください。** コードが全入力DEMを収集します。FMEで入力DEMを前処理する場合は、FeatureWriterのSummary等から、全ファイルの書込み完了後に一度起動してください。通常のWriterの見た目の配置順に依存しない構成にします。

FMEへ結果を読み戻す場合は、成功後にFeatureReaderで `sheet_index.gpkg` または `sheets/*.tif` を読み込みます。FME Flowでは実行ホスト側にも同じPython環境を用意し、サービス実行アカウントからアクセス可能なパスを使用してください。

外周図郭も定寸で出力し、DEM範囲外は透明にします。全画素が透明の図郭は作成しません。索引には実際に出力した図郭だけを記録します。図郭内に部分的な欠損があっても矩形全域の位置・寸法は保持します。

GeoTIFFは内部タイル形式で書きますが、外部ファイルの単位は上記の図郭です。内部タイルと図郭分割を混同しないでください。COG適合やピラミッド作成は今回の対象外です。

写真地図成果の納品仕様では非圧縮TIFF等が指定される場合があります。本コードの標準はRGBA・DEFLATE圧縮の作業用GeoTIFFです。正式納品では製品仕様書のバンド数・透明度・圧縮・拡張子等の指定を確認して調整してください。NONEを指定するだけで全納品条件への適合が保証されるものではありません。

## 図郭の規則と境界処理

標準区画は東西E=-160,000～160,000m、南北N=-300,000～300,000mを対象にします。40km×30kmの大区画に文字を割り当て、5000図郭は10×10分割で番号を付けます。2500図郭は5000図郭を2×2、1000図郭は5×5、500図郭は10×10に分割します。詳細な付番規則は `map_sheets.py` と上記一次資料の第84条を参照してください。標準区画の範囲を超えた場合は停止します。

GeoTIFF側の座標は東方向E・北方向Nです。測量座標のX=N、Y=Eとは軸名の順序が異なります。図郭の東西寸法を画像幅に、南北寸法を画像高さに割り当てます。系番号と投影パラメータを比較し、別系の図郭番号を付ける誤りを防ぎます。

図郭分割は整数画素の窓によるコピーで、再投影も補間も行いません。図郭端は画素の外側境界に一致させます。ワールドファイルの原点は左上画素の中心なので、GeoTIFFの左上隅から半画素ずれた値が正常です。

国土基本図図郭と一致する原点・セルサイズへDEMを先に整合するため、元DEMに格子ずれがある場合はマージ後に1回再サンプリングされます。bilinearを使用します。図郭切出し時に再度サンプリングしません。

## CS画像の独自計算

傾斜は平滑化前のマージDEMから `atan(sqrt(zE²+zN²))` を度で計算します。勾配の求め方は設定 `slope_algorithm` で選べます。既定はHorn法（3×3加重差分、v0.8.0以降）で、`central_difference`（2点の中央差分）を指定するとv0.7.2以前と同じ計算になります。**v0.8.0で既定が変わったため、以前と同じ設定でも傾斜に由来する色が変わります。** PSS版（FMEワークスペース）もHorn法ですが、欠測・外縁・平滑化の扱いが異なるため、画素単位の完全一致は目標にしていません。

曲率指標はGaussian平滑化後の負のラプラシアン `C=-(z東+z西+z北+z南-4z中央)/cell_size²`（1/m）です。凸型を茶系、凹型を青系に配色し、標準設定では固定標高範囲の淡色を15%混ぜ、傾斜に応じて明度を下げます。v0.3.0では下記のcolor設定で色と合成係数を変更できます。曲率指標は断面曲率・平面曲率・平均曲率と同一ではありません。鞍部等で相殺する場合があります。

全域共通の配色係数を使い、各ブロック・図郭の統計で色を変えません。既存CS成果と一致させる必要がある場合は、原典の計算式・平滑化・カラーテーブル・描画モードを確定して `relief()` を置き換える必要があります。

## 色調調整（v0.3.0で追加）

`config.json` の `color` 内で調整します。スライダー画面ではなく、設定ファイル方式です。色は曲率・傾斜・標高から画像化する際に適用し、その後に国土基本図図郭へ切り出します。すべての図郭へ同じ設定を使うため、図郭単位の自動伸張による色違いを作りません。

|color内の設定|初期値|働き|
|---|---|---|
|valley_rgb|[50,96,207]|凹型側の青色。RGB各0～255の整数|
|ridge_rgb|[198,72,59]|凸型側の赤色|
|neutral_rgb|[255,254,190]|曲率0の独立した中間色（黄色）|
|elevation_low_rgb|[36,36,36]|標高色の低標高側|
|elevation_high_rgb|[246,246,246]|標高色の高標高側|
|curvature_strength|1.0|曲率色の濃さ。0～1。小さくすると中間色に近づく|
|elevation_mix|0.15|標高色の混合率。0～1。0なら標高色を混ぜない|
|slope_darkness|0.55|傾斜による暗さ。0～1。下げると斜面が明るくなる|
|brightness|1.0|明るさの倍率。0～3。1より大きいと明るい|
|saturation|1.0|彩度。0～3。0でグレースケール、1より大きいと鮮やか|
|contrast|1.0|中間値127.5を中心にしたコントラスト。0～3|
|gamma|1.0|階調補正。0.1～5。この実装では1より大きいと中間調が明るい|

処理順は「曲率配色→標高色混合→傾斜の暗さ→彩度→コントラスト→明るさ→ガンマ」です。彩度は表示RGBの加重平均を使い、ガンマは `255*(RGB/255)^(1/gamma)` です。線形光空間での測光処理ではなく表示調整です。NoDataのAlphaと地形計算値は色調設定で変更しません。

**まず試す例：暗いCS画像を少し明るく、穏やかにする設定。** 既存のcolorを次で置き換えます。省略した項目は初期値が使われます。

```json
"color": {
  "slope_darkness": 0.35,
  "curvature_strength": 0.75,
  "elevation_mix": 0.08,
  "saturation": 0.85,
  "gamma": 1.10
}
```

設定例を丸ごと読みたい場合は次を使用してください。各ファイルで入力パス、座標系、系番号、セルサイズ、図郭レベル、標高単位の確認を設定してから実行します。

|ファイル|内容|
|---|---|
|config.standard.json|前版と同じ標準色|
|config.light.json|淡色。斜面を明るくし、曲率色を弱める|
|config.terrain_emphasis.json|地形強調。標高色を減らし、彩度・コントラストを少し上げる|
|config.grayscale.json|彩度0のグレースケール|

使いたい設定例をconfig.jsonにコピーすれば、同じFMEの接続で実行できます。既存出力を上書きしないため、調整ごとにoutput_dirを別名へ変更します。この版では色調変更時もマージ・CS計算を含む全工程を再実行します。大きな地域の試行は、同じ設定条件で小範囲から始めてください。

### 調整の使い分けと留意点

- 暗すぎる斜面：まずslope_darknessを下げる。中間調だけ持ち上げたい場合はgammaを上げる。
- 青・茶が濃すぎる：curvature_strengthを下げる。全体の鮮やかさならsaturationを下げる。
- 標高による色被りが不要：elevation_mixを0にする。
- 微地形の曲率色がすぐ飽和する：curvature_limitを大きくする。小さくすると曲率色は強く出る（`color_model:"fme"`でこの値を省略するとFMEマニュアル公式値0.1が自動的に使われる。暫定値0.03を使いたい場合は明示的に指定するか`config.forestry_tuned.json`を使う）。
- brightness・contrast・saturationを上げすぎると0／255へクリップされ、地形の階調が失われる。まず小さく調整する。
- sigma_mは平滑化のスケールで、地形計算そのものを変える。単なる色調調整とは区別する。
- モニター、印刷、背景色で見え方は変わる。プリセットは試行用で、公式CS配色を再現する指定ではない。
- 図郭ごとに異なる設定で作り直すと色が揃わなくなる。採用した設定を全域共通にしてrun.jsonとともに保持する。

## 特に留意すること

- **マージ→CS計算→図郭切出しの順を守る。** 図郭ごとに微分してから貼り合わせると境界に筋が出るおそれがあります。
- **計算ブロックには余白を設ける。** 本コードはGaussian半径と微分に必要な余白を読んで中央だけを書き戻します。NoDataや全域外周に接する範囲は透明です。sigma=3m・セル1mなら13mの余白が必要です。納品対象より広いDEMを用意してください。
- **元データの標高段差は別問題。** 年度・鉛直基準・地表分類方法の違いによる継ぎ目はマージだけでは直りません。断面等で確認してください。
- **入力の重複は後に指定した有効値を優先。** ファイル配列の順序をrun.jsonに記録します。最新年度の自動判定・平均化・段差補正はありません。
- **別の平面直角座標系の地域はジョブを分ける。** 一つの系へ全国を集約せず、測地系も含めて整理します。離れたDEMをまとめると間の空白を含む巨大な矩形画像になる点にも注意してください。
- **セルサイズと図郭レベルは別々に決める。** 5m DEMを1mへ変更しても1m計測相当にはなりません。図郭寸法がセルサイズで割り切れなければ停止します。
- **再実行は新しい出力先へ。** 失敗時の部分成果を混ぜないため自動上書きはしません。run.jsonがcompletedの場合のみ完了です。
- **CS画像から標高値は復元できません。** 標高値が必要な場合は入力DEMを正本として保持してください。`projected_dem.vrt`は入力成果への参照です。

## 検証と限界

作成環境でCS数値テスト6件・図郭テスト9件・色調テスト5件の計20件が成功しました。旧版v0.2.0との比較でも、標準設定のRGBA・傾斜・曲率が人工地形で完全一致しました。図郭寸法、付番、負座標、原点をまたぐ境界、隣接図郭の隙間・重複、画素切出し窓などを確認しています。

作成環境にはGDALがないため、GeoTIFF・TFW・GeoPackageの書出しを含む結合テスト1件はスキップしました。GDALのある実行環境では、同梱テストが人工DEM2枚をマージし、2図郭への分割後の画素値を元のCS画像と比較します。FME実機試験と実DEMでの試験も未実施です。

最初に小さい領域で実行し、図郭索引と既存の正しい図郭データを重ねて位置・番号を確認してください。

## XYZ一括生成（今回追加）

DEMマージ → 色調調整付きCS GeoTIFF → 国土基本図図郭GeoTIFF → XYZ PNG を一括実行します。
平面直角座標系・国土基本図の図郭は `sheets/` のTIFFに適用します。
XYZは一般的なWeb地図との互換性のため **EPSG:3857、256×256ピクセル、北端がy=0** です。
XYZの区切りと国土基本図の図郭は一致しません。色調を再調整せず、図郭群を束ねた `cs_relief.vrt` を再投影します。
透明度を保持し、全ピクセル透明のタイルを省略します。黒色はNoData扱いしません。

出力は `xyz/{z}/{x}/{y}.png` と `xyz/xyz.json`（範囲・枚数・完了状態）です。
全工程の成功は `run.json` の `status: completed` で確認します。
中断・失敗時の出力は部分成果です。既存フォルダーへの追記・途中再開は実装していません。

既定は最小ズーム12、最大16、候補枚数上限100000です（最大ズームはv0.8.0まで18。QGISプラグイン版と同じ16に変更）。ズームを1増やすと広域では枚数がおよそ4倍になります。
上限は透明タイルを省略する前の外接矩形の枚数です。離れた入力の組合せでは大きくなります。
上限超過時はXYZの書出し前に停止します。その時点までのTIFFは残ります。
上限増加の前に小範囲・ズーム12～14で確認してください。拡大ズームを増やしてもDEMの精度は上がりません。
直列処理でタイルごとにGDAL Warp（average）を実行するため、大規模・低ズーム処理には時間がかかります。

Web配信する場合はxyzフォルダーをHTTPサーバーに配置し、
`https://ご自身のサーバー/xyz/{z}/{x}/{y}.png` をXYZ接続に登録します。
サーバー公開は本ツールの処理には含みません。空タイルの404は欠損範囲を意味します。
QGISではブラウザのXYZ Tilesから新規接続を作成し、同じURLとズーム範囲を設定します。

計算に使用するGDAL API: https://gdal.org/en/stable/api/python/utilities.html
CS・TIFF・XYZの計算は指定したPython環境で実行します。LAS/LAZ・不規則点の前処理ではPDALを起動します。

### FMEでの実行

これまでと同じSystemCallerから `run_csmap.cmd` を1回実行します（.fmw自体は含みません）。
設定例を `config.json` にコピーし、入力・出力・座標系を指定します。
既存設定を引き継ぐ場合は、以下のキーをトップレベルに追加してください。

```json
"xyz_enabled": true,
"xyz_min_zoom": 12,
"xyz_max_zoom": 16,
"xyz_max_tiles": 100000
```

`xyz_enabled: false` ならTIFFまでです。XYZ失敗時も終了コードは非0です。
既に作成したCS TIFFだけで新工程を試すこともできます。同じconda環境で次を実行します。

```bat
python xyz_tiles.py --input "D:\output\cs_relief.vrt" --output "D:\output\xyz_test" --min-zoom 12 --max-zoom 14
```
