# 入力形式の選び方・追加機能の操作説明

2026-09-19／FME用 v0.7.1・QGIS用 v0.5.1（試作版）

## 一括処理

入力形式を選択 → 地域フォルダー内のファイルを収集 → DEM化・格子整合 → マージ → 色調調整付きCS画像 → 国土基本図図郭GeoTIFF → XYZ PNG。

平面直角座標系・国土基本図の図郭はTIFFに適用します。XYZはEPSG:3857／256px／北端y=0のPNGです。
CSは従来版の独自方式で、長野県版・既存CSMapとの画素単位の互換実装ではありません。

## 入力一覧

|入力形式|ファイル|設定・動作|
|---|---|---|
|標高ラスタ|`.tif .tiff .img .asc .vrt`|単バンド標高。必要に応じて共通CRS・解像度・格子に整合|
|国土地理院DEM|配布`.zip`・数値標高`.xml`|ZIP内のXMLを直接読み取り、DEM化。手動解凍不要|
|標高テキスト|`.xyz .csv .txt`|列番号、区切り、文字コード、X/Y順、欠測値、入力CRSを指定|
|レーザ点群|`.las .laz`|地表面の選択・分類後、補間してDEM化。PDAL 2.9以降が必要|
|森林航空レーザ成果|`.lem`＋同名`.csv`、XYZ/CSV格子、`.tif`＋`.tfw`、GeoTIFF、これらの`.zip`|フォルダーまたはZIP内を自動判別。森林GISフォーラム標準仕様の標高（DEM）成果を想定|

## 森林航空レーザ成果（新設）

`input_type` を `forest` にすると、同一フォルダーまたはZIP内から次を自動判別します。

|判定対象|判定・処理|
|---|---|
|LEM|同じフォルダー・同じ基底名のCSVをヘッダーとして組にし、固定幅標高値をDEM化|
|CSV／TXT／XYZ格子|先頭100行から区切り、ヘッダー行数、最初の3数値列を判定し、規則格子としてDEM化|
|TIFF＋TFW|GDALでワールドファイルを読み、指定した入力CRSを付与して整合|
|GeoTIFF|内部の位置情報とCRSを読み、共通格子へ整合|
|ZIP|対応ファイルとTFW／PRJ等の側方ファイルだけを安全な作業フォルダーへ展開して上記判定|

LEMは、CSVヘッダーの「東西／南北方向の点数・データ間隔・区画左下／右上X,Y座標」を使用します。LEM本体は北から南のレコード順、各標高値5文字、0.1m単位として読み、`-9999`と`-1111`を欠測にします。測量座標はX＝北、Y＝東です。

森林航空レーザCSVの既定も「X＝北、Y＝東」です。GIS式のX＝東、Y＝北の場合は `forest_axis_order` を `east_north` に変更します。規則格子の間隔は `forest_grid_cell=auto` で座標値から判定します。特殊成果だけメートル単位の数値を指定できます。座標列以外にも数値列が先行するCSVは、汎用の「標高テキスト」入力を選び、列番号を明示してください。

LEMヘッダーの平面直角座標系番号だけではJGD2000／JGD2011／測地成果2024等を確定できないため、LEM、CSV格子、CRSを内包しないTIFFでは `input_crs` の指定が必須です。座標値の格納単位は通常自動判定します。自動判定できない成果だけ `forest_lem_coordinate_scale` に `0.01` または `1.0` を指定します。

標準的な欠測値は `forest_nodata=-9999` です。GeoTIFFにNoDataが設定されている場合は、その値を優先します。ZIPの解凍サイズには安全上の上限を設けています。パス移動を含む不正なZIP、1ファイル512MiB超、対応ファイル合計8GiB超は停止します。

1回の実行では1種類の入力形式を選びます。LASとLAZ、ZIPとXMLなど同じ区分内の混在は可能です。
形式が異なる成果は個別にDEM化した中間TIFFを、標高ラスタ入力でまとめられます。
フォルダー指定はサブフォルダーも検索できます。選択区分の拡張子だけを拾います。
入力専用の地域フォルダーを使ってください。過去の出力TIFFまで混ざる場所を指定しないでください。
地域の範囲は入力ファイルの範囲です。自治体界による自動切抜き・データの自動ダウンロードは含みません。

## QGIS 3.44での操作

1. 旧プラグインを無効にし、「プラグインの管理とインストール → ZIPからインストール」で新版ZIPを指定します。QGISを再起動します。
2. 「CS Map Sheets」の処理を開き、先頭の「入力形式」を選択します。
3. 「入力ファイル」で複数選択するか、「入力フォルダー」を指定します。ラスタは従来の「読込み済み標高ラスタ」からも指定できます。
4. 出力の平面直角座標系、系番号、セルサイズ、図郭レベル、色調、XYZズームを設定します。
5. テキスト・点群の場合は、下記の形式別設定を指定します。関係しない形式の設定項目は処理に使いません。画面上には全形式の項目が表示されます。
6. 入力の標高単位・鉛直基準が統一済みであることを確認し、チェックを入れて実行します。

出力親フォルダーの下に毎回新しい `csmap_日時_識別子` フォルダーを作ります。
中断・失敗した成果を続きから再開する機能はありません。新規フォルダーへ再実行してください。

### PDALの用意（LAS・LAZ／不規則テキスト点のみ）

QGISに点群が表示できても、今回使用する `pdal.exe` が同梱されているとは限りません。
`pdal_wrench.exe` や `python.exe` を代わりに指定することはできません。
FME版用の環境があれば共用できます。新しく用意する場合はMiniforge等のconda端末で実行します。

```bat
conda env create -f environment-pointcloud.yml
conda run -n csmap pdal --version
conda run -n csmap where pdal
```

最後に表示された `pdal.exe` のパスをQGISの「点群用PDAL実行ファイル」に指定します。
例：`C:\Users\利用者名\miniforge3\envs\csmap\Library\bin\pdal.exe`。
PDAL本体やGDALのバイナリーはZIPに同梱していません。依存環境の構築にはインターネット接続が必要です。
地理院XML、通常の標高ラスタ、規則格子テキストの処理ではPDALは不要です。

## FMEでの操作

従来と同じ `Creator（1件）→ SystemCaller → 終了コード判定` で実行します。
完成した `.fmw` は同梱していません。Python実装と起動CMDをSystemCallerから使用する方式です。

1. `environment.yml` で環境を作成します。既存のcsmap環境は以下で更新できます。
2. 使用形式に合う `config.*.json` を `config.json` にコピーします。
3. 入力フォルダー、出力先、CRS・系番号・解像度・色調等を変更します。
4. `run_csmap.cmd` のcondaパスを実機に合わせ、SystemCallerから1回実行します。

```bat
conda env update -n csmap -f environment.yml
```

|設定例|用途|
|---|---|
|config.gsi_zip.json|地理院ZIP/XMLの地域フォルダー|
|config.raster_folder.json|納品GeoTIFF等のフォルダー、格子整合あり|
|config.text_grid.json|規則格子の座標テキスト|
|config.text_points.json|不規則な標高点テキスト、PDAL補間|
|config.las_classified.json|分類済みLAS/LAZ、地表面クラス2|
|config.las_ground_only.json|地表面点のみのLAS/LAZ|
|config.las_auto.json|未分類LAS/LAZ、SMRF自動分類|
|config.forest_airborne_laser.json|森林航空レーザ成果フォルダー／ZIPの自動判別|

FMEの公開パラメータで選択できるよう、コマンドラインの上書き引数も用意しました。
`input_type` に相当する選択肢は `raster / gsi / text / lidar / forest` です。
`lidar_mode` は `classified / ground_only / auto` です。
以下の引数はconfig.jsonより優先されます。フォルダー指定または個別ファイル指定は、設定内のinputsを置き換えます。

```bat
run_csmap.cmd --input-type lidar --input-folder "D:\DEM\地域A" --lidar-mode classified --output-dir "D:\CSMAP\地域A_新規"
```

個別ファイルは `--input-file` をファイルごとに繰り返します。

```bat
run_csmap.cmd --input-type lidar --input-file "D:\DEM\地域A\01.laz" --input-file "D:\DEM\地域A\02.laz" --output-dir "D:\CSMAP\地域A_新規"
```

使用可能な引数：`--input-type`、`--input-folder`、`--input-file`、`--input-crs`、`--output-dir`、`--lidar-mode`、`--pdal`。`--input-folder`と`--input-file`は同時指定できません。
JSONの入力CRS欄は文字列EPSGコード等、QGISではCRS選択欄です。
終了コード0は全工程成功です。`run.json` の `status: completed` も確認してください。

## LAS・LAZの地表面設定

|選択|処理|
|---|---|
|分類済み|指定分類コードを抽出。既定は2。樹冠のクラス等は使用しません|
|地表面点のみ|分類コードによる絞込みをせず使用。地表面だけの納品成果であることを確認してください|
|自動分類|SMRFで地表面を推定し、クラス2からDEM化。元の分類値は判定前にリセット|

全LASモードでWithheld点とノイズ分類7・18は除外します。末端リターンを無条件に地表面とはみなしません。
LASの座標はヘッダーのscale・offsetをPDALで適用し、通常のX=東・Y=北として扱います。
テキスト用のX/Y入替設定はLASへは適用しません。

Windows版PDALが日本語を含むパスを扱えない場合、v0.6.1は処理中だけASCII名の作業用ハードリンクを作成し、作成できない場合だけコピーします。元ファイルは変更しません。ログの `Selected point input` がFME／設定から選ばれた入力、`PDAL ASCII input` がPDALへ実際に渡した一時パスです。出力フォルダー自体は半角英数字だけのパス（例：`C:\gis_data\output`）を推奨します。
複合・3次元CRSしかない場合は入力の水平CRSを明示してください。標高の変換は実施しません。
PDALのLAS Readerが扱わない波形付きPoint Format 4・5・9・10は対象外です。

### 補間と分割

- IDW（距離重み付け）、近傍点の平均、近傍点の最低値を選択できます。最低値だけで未分類点群を地表面化する使い方は推奨しません。
- 半径は出力セル中心からのメートル距離です。既定2m。半径内に有効な点がないセルはNoDataです。追加の広域穴埋めは行いません。
- 既定512×512画素ごとに処理し、隣接ファイルからバッファー内の点も読みます。補間後に中央部を切り出すため、分類済み点ではブロックごとの補間切れを抑えます。
- 自動分類ではSMRFの窓幅も考慮したバッファーを使います。ただし分類はブロック単位で、全地域を一括分類した結果との一致は保証しません。
- 自動分類は対象範囲の点をストリーミングで一時LAZに切り出し、既定1,000万点以下の部分点群をメモリー処理します。上限超過時はブロックの画素数を減らすか、メモリーに応じて上限を変更してください。点は自動間引きしません。
- 通常LASは空間索引がないため、重なる入力ファイルを複数回走査します。巨大な単一LASより、地域・図郭で分割済みのLAS/LAZの方が効率的です。
- 自動分類の一時・確認用LAZはXYZを1mm単位で保存する分類確認用データです。RGB等の全属性・元ファイルの全メタデータを保全するコピーではありません。元の納品ファイルは変更しません。

SMRFのセル幅・傾斜係数・閾値・標高差係数・窓幅は詳細設定にあります。
森林GISフォーラムが特定のSMRF設定を承認しているという意味ではありません。
急斜面、崖、密な下層植生、橋、地表面点が少ない場所では分類結果を確認してください。

## テキストの設定

- 文字コード：通常 `utf-8-sig`、従来の日本語Windows納品では `cp932` 等を指定。
- 区切り：カンマ／タブ／空白／セミコロン。先頭ヘッダー行を飛ばす行数を指定。
- 列番号は1始まり。例：番号、X、Y、Zなら `2,3,4`。
- 測量のX=北・Y=東の場合は「北方向、東方向」を選択。
- 欠測値は入力NoData欄で指定。標高0や負の標高は、それ自体を欠測とはみなしません。
- 規則格子はメートル単位の投影CRS、格子間隔を指定。座標をセル中心としてTIFFを復元し、共通出力格子へ整合します。欠けた格子点はNoData。同じ座標に異なる標高が重複すると停止します。
- 不規則点はPDALで補間します。緯度経度点は列順を経度・緯度にし、正しい地理CRSを指定します。
- 固定長レコード、独自ヘッダーが各所に入るテキスト、独自バイナリーは対象外です。該当ファイル・仕様書に合わせた追加の読込み定義が必要です。

## 地理院XMLの扱い

GMLのDEM要素、緯度経度のEnvelope、GridEnvelope、Linearの走査順、startPoint、tupleListを読みます。
先頭・末尾で省略された格子の位置を保持し、標高-9999、データなし、海水面はNoDataとします。
UTF-8及び従来のShift-JIS XMLを読みます。標高DEM以外のメタデータXML等は成果に含めません。
1つのXMLは最大256MiB、原格子は既定2,500万画素までです。
ZIPの内部パスは展開せずに読み、別フォルダーへのファイル書込みを防ぎます。ZIP内のさらにZIPは扱いません。
同一CRS・解像度・格子の連続入力は先にモザイクし、隣接する標高を使って再投影します。
異なる解像度・計測時期のデータを重ねても標高差そのものは補正されません。

`fguuid:jgd2024.bl` は、水平座標の計算にはJGD2011と共通のEPSG:6668を使用し、XMLの元の名称を処理記録へ残します。
これは標高値を測地成果2011へ戻す操作ではありません。標高は入力の値を維持します。
JGD2024表記とJGD2011/JGD2000表記のXMLが同じ実行に混在する場合は停止します。
標高基準を事前にそろえ、変換済みのTIFF等で入力してください。

## 出力・重複・確認

`projected_dem.vrt`、`cs_relief.vrt`、`sheets/`、`sheet_index.gpkg`、`xyz/`、`run.json` に加え、入力変換を行った場合は `input/` ができます。県全域も図郭単位で処理されます。
`input/input_report.json` に入力と変換結果、`input/point_sources.json` に点群情報を記録します。
自動分類時の `input/block_*_classified.laz` はバッファー付きで隣接ブロックと重複します。分類結果の点検用です。
内部DEMのNoDataは `-999999` に統一します。標準仕様書の納品NoData値との同一性は保証していません。

ラスタ・地理院・規則テキストの重複部は、後の有効入力が優先されます。
フォルダーはパス名の昇順です。計測日の新しさや解像度を推定して優先する処理はありません。
点群の重複部分は補間の対象点としてまとめて使うため、重複点を自動削除しません。
計測時点・標高基準が異なる成果を混ぜる前に、利用するデータを選別してください。

この版では全形式の入力に対しメートル標高・同一鉛直基準の確認を求めます。楕円体高から標高への換算や、標高改定パラメータの適用は含みません。

まず小範囲を、XYZズーム12～14程度で実行してください。既知の標高、座標、NoData、図郭境界とCSの継ぎ目を確認します。
コード・数値テストの結果と、実機未検証項目は `VALIDATION.txt` を参照してください。
